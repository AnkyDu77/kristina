# Кристина

Личный помощник в Telegram. Ты пишешь, open-weight LLM (по умолчанию
Qwen3.6-27B) думает и при необходимости сама ищет в интернете, читает
страницы, ходит браузером, запускает код в своей песочнице, работает с
присланными файлами и запоминает важное о тебе. Отвечает текстом. Итог
крупной задачи говорит **кружком**: голос Qwen3-TTS, губы MuseTalk.

```
Telegram ──► kristina-bot (Go, CPU-VPS, работает всегда)
               │  sqlite: история, память, подтверждения, отложенные вопросы
               │  агент: модель → инструменты → модель (до KRISTINA_AGENT_MAX_STEPS)
               │    web_search, read_page  — на VPS бота + Parallel Search MCP
               │    remember, forget       — только после ✅ владельца
               │    start_task             — фоновая задача: план, вопросы, итог
               │    create_monitor         — слежка за страницей, без LLM и GPU
               │    *_file, run_command    — workspace + песочница (docker, без сети)
               │    <сервер>_*             — внешние MCP-серверы (KRISTINA_MCP_SERVERS)
               │  GPU спит → вопрос/задача ждут, кнопка «🟢 Разбудить»
               ▼
         GPU VPS Selectel (nginx :8080, Bearer-ключ), будит только владелец
               ├─ /llm/      llmster (headless LM Studio) + Qwen3.6-27B
               ├─ /browser/  Playwright MCP: headless Chromium, сеть — только интернет
               ├─ /tts/      Qwen3-TTS 1.7B: клон голоса по эталону, VoiceDesign
               └─ /lipsync/  MuseTalk 1.5: аватар готовится один раз, рендер ≈ realtime
```

## Состав

| Каталог | Что внутри |
|---|---|
| `kristina-bot/` | Go-бот: Telegram long-poll, агент с инструментами, sqlite (modernc, чистый Go), менеджер GPU (terraform apply/destroy + авто-стоп по простою, урезанная копия из lmify-ui) |
| `media/` | `docker-compose.yml` медиа-стека: `tts/` (FastAPI + Qwen3-TTS), `lipsync/` (FastAPI + MuseTalk 1.5) |
| `selectel/` | terraform GPU VPS: Docker + nvidia-container-toolkit, llmster, S3-кэш образов, весов и моделей, nginx-гейт |
| `assets/` | `face.png`: фото Кристины; `idle.mp4`: idle-луп из него (аватар по умолчанию) |
| `tools/` | подготовка без GPU: веса и образы → S3, idle-луп на маке ([tools/README.md](tools/README.md)) |

## Агент

На каждом ходе модель решает: ответить или вызвать инструмент. Сами
инструменты работают на VPS бота, карта нужна только «мозгу».

| Инструмент | Что делает | Подтверждение |
|---|---|---|
| `web_search` | поиск через [Parallel Search MCP](https://docs.parallel.ai/integrations/mcp/search-mcp): бесплатно, без ключа | нет |
| `read_page` | сначала читаем страницу сами, с VPS. JS-сайты, PDF и длинные страницы под цель уходят в Parallel `web_fetch` | нет |
| `remember` | запомнить факт о тебе | ✅ / ❌ кнопкой |
| `forget` | забыть запись по номеру | ✅ / ❌ кнопкой |
| `start_task` | (в чате) поставить фоновую задачу | нет |
| `update_plan`, `ask_user` | (в задаче) план в карточке, вопрос владельцу | — |
| `create_monitor` | следить за страницей | ✅ / ❌ кнопкой |

- **Подтверждения.** Под действием с последствиями появляются кнопки. Ждём
  `KRISTINA_APPROVAL_TIMEOUT` (10 минут). Квитанции хранятся в таблице
  `actions`. Нажатие ровно одно: повтор, гонка с таймаутом и кнопки
  прошлого процесса отвечают «уже неактуально».
- **Безопасность.** Выдача инструментов для модели — данные, а не
  указания. Поэтому запись в память только с подтверждения: страница,
  которая пишет «запомни…», сама ничего не запишет. `read_page` ходит только в
  публичный интернет. Проверка идёт по реальному IP после DNS, на каждом
  редиректе: localhost, приватные сети и 169.254.169.254 закрыты, а рядом
  с ботом лежат terraform state и ключи. Внутренний адрес не уходит и в
  Parallel.
- **Что уходит наружу.** В Parallel уходят поисковые запросы, цели и адреса
  страниц, которые не удалось прочесть самим. Сюда же — случайный id чата
  для лимитов бесплатного тарифа.
- **История.** В модель уходят последние `KRISTINA_HISTORY_TURNS` вопросов
  и ответов. Ход агента (вызовы и выдача) в историю не попадает, чтобы не
  съедать контекст. Он хранится в `tool_runs`. Везде soft delete: `/reset`
  и `/forget` прячут запись от модели, но из базы её не удаляют.

## Фоновые задачи

Большое («сравни», «исследуй», «собери») Кристина ставит фоновой задачей
сама (`start_task`). Можно и руками: `/task <что сделать>`. Задача идёт
вне очереди чата: пока она работает, с Кристиной можно разговаривать.

- **Карточка.** Одно сообщение, которое переписывается: статус, план
  (✅ ▶️ ▫️), текущий шаг и кнопки ⏸ Пауза / ▶️ Продолжить /
  ✖️ Отменить / 🔁 Повторить. Итог приходит отдельным сообщением, попадает
  в историю чата (о нём можно переспросить) и говорится кружком.
- **Вопросы и подтверждения паркуют задачу.** `ask_user` присылает вопрос
  с вариантами-кнопками (или ответь реплаем). Действие с последствиями
  присылает ✅ / ❌. Пока ты думаешь, задача лежит в базе (`waiting`) и
  ничего не занимает, раннер берётся за следующую. Ответил — задача
  продолжает с того же места.
- **Ход задачи сохраняется после каждого шага.** Рестарт бота, сон карты
  посреди задачи, пауза на сутки — задача продолжит с последнего шага.
  Если ход перестаёт влезать в контекст, старая выдача инструментов
  сокращается.
- Задачи идут по одной: карта одна. Потолок — `KRISTINA_TASK_MAX_STEPS`
  (25) вызовов инструментов, дальше Кристина подводит итог тем, что есть.

## Мониторы

«Напиши, когда появится в наличии / выйдет версия / изменится страница».
Мониторы работают **без LLM и без видеокарты**: бот сам скачивает
страницу, сравнивает её с прошлой версией и пишет тебе.

```
/watch https://…                    — когда страница изменится (с выжимкой: что появилось)
/watch https://… "В наличии"         — когда текст появится
/watch https://… !"Нет в наличии" 2h — когда пропадёт; интервал 30m, 2h… (по умолчанию 1h, не чаще 10m)
/watches, /unwatch <номер>
```

Кристину можно попросить и словами: тогда она вызовет `create_monitor`, и
ты подтвердишь кнопкой. Алерт приходит только на смену состояния. Если
страница лежит, проверки становятся всё реже (до раза в сутки), а на
третьем сбое подряд приходит одно предупреждение. Под алертом есть кнопка
«🧠 Разобрать»: она отправляет Кристине обычный вопрос, а если карта спит,
вопрос встаёт в очередь. Страницы, которые рисует JavaScript, мониторы
пока не видят: браузер появится в фазе 3.

## Компьютер Кристины

### Браузер

Headless Chromium ([Playwright MCP](https://github.com/microsoft/playwright-mcp))
поднимается на GPU-машине вместе с «мозгом» и гаснет вместе с ней, так
что отдельной машины не держим. Бот ходит в него через nginx-гейт
(`/browser/mcp`, медиа-ключ) и показывает модели инструменты `browser_*`,
только пока карта не спит. Скриншоты приходят тебе в чат.

| Можно свободно | Только с ✅ | Модели не даём |
|---|---|---|
| открыть, назад, снимок страницы, клик, наведение, клавиша, выбор в списке, ожидание, вкладки, скриншот | ввести текст, заполнить форму, ответить на диалог сайта | свой JS (`browser_evaluate`, `run_code`), сетевые запросы в обход страницы, загрузка файлов |

Адрес открываемой страницы может подсунуть сама страница. Поэтому у
браузера своя docker-сеть, и iptables выпускает из неё только в интернет:
метаданные облака (169.254.169.254), приватные сети и сервисы самой
машины закрыты. Бот вдобавок не пустит `file://` и прочие не-http схемы.
Образ берётся из S3-кэша (`browser_image`). Отключить браузер:
`browser_enabled = false`. Браузер где-то ещё: `KRISTINA_BROWSER_URL`, и
тогда карта ему не нужна.

### Песочница и файлы

`data/workspace` бота — общая рабочая папка. Присланный в Telegram документ
или фото ложится в `inbox/`. Если у файла есть подпись, Кристина сразу
берётся за него. Без подписи файл просто сохраняется, и модель не
зовётся.

- `list_files`, `read_file` (текст, код, PDF текстовым слоем), `write_file`,
  `send_file` (прислать тебе документом). Пути — через `os.Root`: ни `..`,
  ни симлинк, созданный в песочнице, не выводят за пределы workspace
  (например, к `.env` бота).
- `run_command`: `sh -c` в контейнере `kristina-sandbox` с той же
  `/workspace` (python3, go, git, jq, ripgrep). Пользователь 1000 без
  capabilities, корень только на чтение, `--network none`, 1 GB / 1 CPU /
  256 процессов, 60 секунд на команду. Без сети подтверждать нечего; с
  сетью (`KRISTINA_SANDBOX_NETWORK=bridge`) каждая команда идёт с ✅.
- Песочницу запускает бот через сокет докера. Сокет даёт root на хосте,
  но он у бота, а не у модели: та может только «выполни в песочнице».
  Без докера (или с `KRISTINA_SANDBOX=off`) файлы работают, а
  `run_command` пропадает.

### Внешние MCP-серверы

`KRISTINA_MCP_SERVERS=docs=https://…/mcp,mine=https://…/mcp`, ключ —
`KRISTINA_MCP_TOKEN_DOCS`. Инструменты появляются как `docs_<имя>`. Без
подтверждения вызываются только те, что сервер сам пометил как
read-only (`readOnlyHint`), остальные — с ✅.

## Деньги: карта работает, только пока Кристина думает

- **Сообщения карту не будят.** Если карта спит, вопрос записывается в
  очередь (`inbox`), а под первым из них появляется кнопка
  «🟢 Разбудить сейчас» (только для `KRISTINA_GPU_ADMIN_TGIDS`). Вопросы
  можно копить. Когда карта проснётся (кнопкой, `/wake` или после
  рестарта бота), Кристина ответит на всю очередь **одним прогоном**
  модели.
- **Без карты работает всё, кроме «думать» и «говорить»:** `/memory`,
  `/remember`, `/forget`, `/status`, `/reset`, `/circles`, `/tasks` и
  кнопки задач, мониторы целиком, кнопки подтверждений.
- **Задачи карту не будят.** Задача, поставленная при спящей карте, ждёт
  в очереди: в её карточке есть кнопка «🟢 Разбудить видеокарту». Ожидание
  твоего ответа карту не держит.
- **Карта занята только на время хода модели.** Пока идёт поиск или ты
  думаешь над кнопкой, watchdog считает это простоем. Через
  `KRISTINA_GPU_IDLE` простоя карта гаснет. Если её погасили посреди
  ответа, вопрос уходит в очередь, а не теряется.
- **Кружки редкие.** Кружок записывается по итогу фоновой задачи, по
  ответу в чате, который потребовал `KRISTINA_CIRCLE_MIN_TOOLS`
  (по умолчанию 3) вызовов инструментов, и по `/circle`. Ради кружка карту
  не будим. `/circles off` отключает и кружки за задачи.
- **Кэш в S3.** Веса и базы образов (torch, mmcv, MuseTalk) лежат в
  `s3_cache_uri`. Если базы в кэше нет, GPU-машина один раз собирает её
  сама (lipsync — 20–40 минут) и кладёт в S3. Дальше подъём занимает
  минуты. Сервис — тонкий слой с `server.py` поверх базы, он собирается
  на машине за секунды. Поэтому правки кода бесплатны, а пересборку
  базы запускает только правка `media/<сервис>/base/`.
- **Прерываемый инстанс** (`tags = ["preemptible"]`, как в lmify).
- **Карта.** Медиа-стек (TTS + MuseTalk) занимает ~17 GB VRAM. Вместе с
  Qwen3.6-27B Q4_K_M (~17.5 GB с mmproj) и KV-кэшем на 32k нужна карта с
  48 GB. С внешним «мозгом» (`KRISTINA_LLM_BASE`) хватит и 24 GB, и
  тогда текстом Кристина отвечает даже при спящей карте.

## Запуск

### 0. Что понадобится

- Бот у @BotFather и свой tg_id.
- «Мозг» — любой OpenAI-совместимый эндпоинт. Проще всего lmify:
  `http://<ip>:8080/v1` + ключ, модель `qwen3.6-27b`. По умолчанию
  «мозг» живёт на той же GPU (`llm_model_path` в `selectel/`).
- Бакет Selectel S3 под кэш **в том же проекте**, что и GPU (S3-ключи
  проектные, см. грабли lmify).

### 1. GPU VPS

```bash
cd selectel
cp terraform.tfvars.example terraform.tfvars   # заполнить
terraform init
```

Руками `apply` делать не нужно, это сделает бот. Для отладки можно и
руками: `terraform apply`, затем `terraform output -raw health_check_command`.

### 2. Бот

```bash
cd kristina-bot
cp .env.example .env   # токен, tg_id, LLM, KRISTINA_MEDIA_KEY = ключ из api_keys
go run .
```

На VPS:

```bash
docker compose --profile sandbox build sandbox   # образ песочницы, один раз
docker compose up -d --build
```

Весь каталог `kristina/` должен лежать в `/root/kristina` (см.
`kristina-bot/docker-compose.yml`), а IP этой VPS нужно добавить в
`allowed_ssh_cidr` и `allowed_api_cidr`. Проверить песочницу вживую:
`/computer` в боте или попросить Кристину выполнить `id -u && go version`.

### 3. Голос

У Кристины пока нет голоса. Его придумывают описанием (Qwen3-TTS VoiceDesign):

```
/wake
/design молодая женщина, около 25 лет, низкий спокойный тембр, говорит неторопливо и чуть насмешливо
/design ...   ← пробуй, пока не понравится
/keep
```

`/keep` сохраняет удачный сэмпл в `kristina-bot/data/voice/ref.wav` +
`ref.txt`. Дальше каждый ответ клонируется с него. Свой эталон тоже
подойдёт: положи туда wav на 5–15 секунд и точную расшифровку.

### 4. Аватар

По умолчанию аватар — `assets/idle.mp4`: 8-секундный idle-луп, который
LivePortrait сделал из `assets/face.png` прямо на маке (моргания, лёгкие
движения головы, рот закрыт). Как сделать другой, описано в
[tools/README.md](tools/README.md#в-живое-лицо-idle-луп-на-маке-бесплатно).
Аватар определяется хэшем файла, поэтому новый луп подготовится на GPU сам
при первом кружке.

## Команды бота

| | |
|---|---|
| любой текст | вопрос агенту. Если карта спит, вопрос уходит в очередь |
| `/task <что сделать>`, `/tasks` | фоновая задача и список задач. Управление — кнопками карточки |
| `/watch <адрес> […]`, `/watches`, `/unwatch <номер>` | мониторы страниц (см. выше) |
| файл / фото | ложится в `workspace/inbox/`. С подписью Кристина сразу за него берётся |
| `/files [папка]`, `/computer [reset]` | что лежит в workspace; песочница и её пересоздание (файлы остаются) |
| `/memory` | что Кристина о тебе помнит, с номерами |
| `/remember <факт>`, `/forget <номер>` | запомнить или забыть сразу, без подтверждения: ты владелец |
| `/circle` | сказать последний ответ кружком (если карта не спит) |
| `/circles on\|off` | кружки за крупные задачи: да или нет |
| `/wake`, `/sleep` | разбудить или погасить GPU: только tg_id из `KRISTINA_GPU_ADMIN_TGIDS`. Гаснет она и сама, после простоя |
| `/gpu`, `/gpu full` | состояние карты: загрузка, VRAM, температура, питание, кто сколько памяти занял, когда погаснет; `full` — сырой `nvidia-smi`. Спящую карту не будит и простой ей не продлевает. Словами («сколько свободно VRAM?») — Кристина спросит сама (`gpu_status`) |
| `/design <описание>`, `/keep` | сэмпл нового голоса и его выбор |
| `/status` | GPU, очередь, память, история, голос |
| `/reset` | забыть разговор. Память о тебе остаётся |

## Подготовка до GPU

Веса заранее кладутся в S3-кэш (`tools/fetch_weights.sh` на маке).
Базы образов можно собрать заранее на любой amd64-VPS с Docker
(`tools/build_images.sh`) или доверить первую сборку самой GPU-машине:
она положит результат в тот же кэш. Подробности — в
[tools/README.md](tools/README.md).

## Что не проверено вживую

Проверено: `go vet`/`go test`, `terraform validate`, `bash -n` на
setup-скрипте, `py_compile` на сервисах; idle-луп отрендерен на маке. На
живой карте стек ещё не запускался. Что осталось из рисков:

1. **Сборка `lipsync`**: mmcv 2.0.1 под torch 2.0.1/cu118 через `mim`.
   Ловится заранее, на CPU-VPS (`build_images.sh`). Когда заведётся,
   закрепи коммит MuseTalk (`MUSETALK_REF` в Dockerfile).
2. **face-parse с Google Drive**: ловится заранее, в `fetch_weights.sh`.
3. **Qwen3-TTS c `sdpa`**: flash-attn сознательно не ставим. Импорт
   проверяется заранее, а сам синтез — только на карте.
4. **Ударения.** Qwen3-TTS иногда ошибается в русских ударениях. Следующий
   шаг — RUAccent перед синтезом, но сначала проверить, понимает ли модель
   знаки ударения.
5. **Драйвер 535 (CUDA ≤ 12.2).** torch в TTS закреплён `constraints.txt`
   (qwen-tts иначе тянет свежий), версия CUDA проверяется в `build_images.sh`.
